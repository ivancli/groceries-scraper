# CLAUDE.md

## Working on tickets

- **Branch first.** Never commit to `main`. Before making changes, create a descriptively named branch off an up-to-date `main` (e.g. `feat/<ticket>-short-summary`, `fix/<ticket>-short-summary`).
- **Keep docblocks and comments concise.** Explain *why*, not *what* the code already says. One line where possible; no restating signatures, types or obvious behaviour.
